# Режими, настройки и content проверки

## Локално изпълнение

```bash
pnpm test:smoke        # 9 ключови проверки: homepage, двата продукта, cart и keyboard
pnpm test:full         # всички @full проверки
pnpm test:visual       # visual regression + inventory snapshots
pnpm test:content      # DOM правопис върху общия inventory
pnpm test:full --project="Mobile Chrome"
pnpm test:full --project="Mobile Safari"
```

По подразбиране runner избира само `Desktop Chrome`. Използвайте повторени
`--project` аргументи за повече браузъри. Всички проверки са локални; не са добавени
GitHub Actions или активен scheduler. За ежедневен smoke и периодичен full използвайте
тези команди в собствен локален scheduler след настройване на магазина.
`--grep` изрично заменя preset филтъра. Режимът/филтрите се записват в metadata.
Паузите 5–8 секунди между тестовете и 2–4 секунди между навигации/API остават.

## Site configuration

Добавете настройки директно към магазина в `sites.json`:

```json
{
  "name": "My Store",
  "slug": "my-store",
  "url": "https://my-store.myshopify.com",
  "productHandle": "first-product",
  "productHandle2": "second-product",
  "searchTerm": "product",
  "locale": "bg-BG",
  "timezoneId": "Europe/Sofia",
  "capabilities": { "newsletter": false, "reviews": false },
  "selectors": { "addToCart": "button[name='add']", "productTitle": "h1" },
  "thresholds": {
    "lighthouse": { "performance": 60 },
    "visual": { "maxDiffPixelRatio": 0.02 },
    "accessibility": { "maxBlocking": 0, "maxViolations": 10, "maxContrastNodes": 5 }
  },
  "inventory": {
    "discoverProducts": false,
    "productLimit": 5,
    "pages": [{ "path": "/policies/privacy-policy", "type": "static", "language": "bg" }]
  },
  "spelling": {
    "mode": "report",
    "languages": ["bg", "en"],
    "allowWords": ["Zerno", "Зерно", "Shop Pay"],
    "acceptedFindings": [],
    "excludeSelectors": [".customer-review"],
    "maxFindings": 0
  }
}
```

`false` capability изключва съответните сценарии преди заявки и ги маркира
`not-applicable`. `true`/непосочено изпълнява съществуващите проверки; техните
неуточнени skips остават видими като непълен coverage. Поддържаните capabilities
и основните selector overrides са описани в `config/site-settings.d.ts`.
Селекторите са CSS и се валидират преди първата навигация. Непосочените thresholds
наследяват defaults; не е нужно да се повтаря целият обект.

## Единен inventory

`page-inventory.json` е в папката на магазина/run. Основата е home, известните
продукти, collection, search, cart и конфигурираните static страници. Всеки запис
пази URL, type и language. Не се търсят неизвестни policy/contact страници.

Допълнителният `/products.json` crawl е opt-in, ограничен с `productLimit` (1–25).
Прави се веднъж в setup; продуктови проверки, axe, screenshots и spelling четат
същия записан списък. Откритите допълнителни продукти се проверяват чрез отделни
inventory сценарии със steps по URL и attachments. Coverage на dashboard е на
тестовите сценарии, не на отделните steps/URL-и.

## Правопис

Локални `nspell`, `dictionary-bg` и `dictionary-en`; няма cloud заявки. Проверява
се видим DOM текст, labels, `alt`, `title`, `aria-label` и placeholders. Не се
извличат input values, script/style, скрити и editable области. Български текст с
латински думи използва английския речник за тези думи. Смесени кирилица/латиница
се отбелязват. Неподдържани езици са изрично записани; strict не ги приема за проверени.

- `off`: изключено; content сценарии са неприложими.
- `report` (default): находки и контекст, без проваляне за непознати думи.
- `strict`: проваля при неприети находки над `maxFindings` или непроверен език.

`allowWords` приема марки/имена/термини, включително фрази (позволяват се и техните
думи). `acceptedFindings` приема fingerprint IDs от отчета за изрично одобрени
находки. JSON и screenshot са прикачени към теста. Общият `spelling.json` обединява
находки по text/language/component/source/word, запазвайки всички URL-и и locators
с координати. Header/footer грешката не се умножава по страници или браузъри.
Visual проверките правят spelling audit преди снимката; оригиналната снимка не се
рисува/маркира. Това е речникова проверка, не пълна граматика или гаранция за липса
на грешки. OCR за текст, нарисуван в изображения/canvas, остава бъдещо допълнение.

## Dashboard, mobile и качество

Dashboard сравнява сценарии с предишния run на същия магазин: new/recurring,
resolved и unverified failures. Skipped/нестартирал сценарий не доказва resolved.
Когато липсва per-scenario baseline, сравнение не се измисля. New означава новонаблюдаван failure; липсващ/филтриран предишен сценарий не доказва новопоявил се дефект. Показват се посетени
URL-и (не непременно дефект във всеки URL), screenshot и Trace ZIP линкове.

`Mobile Chrome` (Pixel 7) и `Mobile Safari` (iPhone 13) имат touch/device параметри.
Keyboard journey проверява достигане на header link чрез Tab и Escape/focus return
за mobile menu. Axe използва WCAG 2.2 AA tags; автоматизираната проверка не покрива
всички критерии и не замества човешки accessibility преглед.

```bash
pnpm check                  # type-check, lint, unit tests, Docker/Playwright match
pnpm test:p2:local           # речници, DOM privacy/attributes, strict, inventory и real touch context
pnpm test:reporting          # metadata/coverage/retries
pnpm dashboard:preview      # офлайн примерен интерфейс
```

Официални източници: [nspell](https://github.com/wooorm/nspell),
[dictionaries и лицензи](https://github.com/wooorm/dictionaries),
[axe WCAG tags](https://www.deque.com/axe/core-documentation/api-documentation/).
Речниците имат собствени лицензи, запазени в инсталираните packages; вижте
`node_modules/dictionary-bg/license` и `node_modules/dictionary-en/license`.
