## Evidence and interpretation

Open the run's Playwright HTML report from **Reports**, expand a `modern web` or shared-page scenario, and open its attachments:

- `modern-web.txt`: findings with rule, severity, guide ID, element selector, observed facts and suggested fix.
- `modern-web.json`: schema version 1, URL, viewport, element counts, animation support/counts and structured findings.
- `modern-web-warning` annotations: recommendations are recorded even on passing scenarios.

Errors enter existing failed-scenario reporting/comparison. Recommendations do not reduce pass rate. Passing means the checks completed without a detected blocking error; review recommendations separately. There is no aggregate Modern Web score or automatic finding-resolution tracking yet.

The passive inspector reads the current main document (with a separate bounded open-shadow sample) and compares no-preference/reduce motion after two animation frames. It restores the originally observed preference in `finally`. This passive phase does not fill fields, submit forms, click controls, scroll or navigate a second time; the separate Full-only guarded probes below do focus and edit empty synthetic fields. The site may fetch its normal resources in response to media changes. Full adds one visit per configured URL; Pages reuses its existing visit. Existing pacing, rate-limit handling and browser fixtures remain active. Input values and form action URLs are omitted from evidence; page URLs/selectors still need the usual care when sharing reports.

## Limits of this first implementation

- The largest viewport image remains a heuristic. Where available, the separate foreground LCP entry supplies observed image attribution and timing subparts; restricted timing is null. No field INP is produced. Missing width/height attributes are not treated as layout defects: CSS or containers may reserve space correctly.
- Caption presence does not establish quality; absence may have an accessible external player or no meaningful audio. Decorative-video detection is heuristic.
- Motion covers currently running persistent spatial animations in the viewport. It excludes short/interaction-triggered states not currently running, canvas, animated images, flash limits and pause-button operation. Slower or changed-keyframe alternatives are accepted for review, not certified safe.
- No successful form submission is attempted. Guarded Full probes exercise bounded invalid/correction states; complete async validation and actual credential transport are not established. Error text may be generic. Missing references can be transient: confirm reproducibility before fixing the store.
- Hidden/disabled controls and iframes are outside the base DOM scope. A separate bounded component inspector now samples open-shadow naming, ARIA references and observable disabled form participants; closed roots/private internals remain unverified. Empty/unsupported scope must not be read as comprehensive compliance.

It probes at most five empty supported required fields and five checkbox controls. Existing values are left untouched, including prefilled replacements after a rerender (covered by a regression fixture); no successful submit is attempted. Initial/invalid-blur/native-invalid/corrected states and Space-toggle reversal are recorded in `modern-web-interactions.json`/`.txt`. The guard is an HTTP/WebSocket test quarantine, not a general JavaScript sandbox. Network-dependent results are labeled unverified when traffic is blocked. It can intentionally prevent async validators from completing; their outcome is not a clean bill of health.

`modern-web-presentation.json`/`.txt` adds narrow and landscape reflow/occlusion, user text-spacing and 200% root-font stress, light/dark preference contrast/name samples and forced-color support/geometry observations. Temporary styles and preferences are restored. These probes are store test stimuli, not changes to the control-panel design. CSS injection or forced-color unavailability is recorded; it must not be read as a pass. They do not emulate a real OS font-size or virtual keyboard, certify all dynamic backgrounds, or test an authenticated theme preference.

The shared vitals attachment now records initial-visibility provenance and first-hidden time, observed LCP element/priority and available resource timing, event input/processing/presentation estimates, and optional long-frame/script/style/layout diagnostics. The presentation-delay estimate inherits Event Timing quantization. Resource restrictions/unsupported APIs stay explicit; this is not field INP. Passive sampling is finalized at `modern-web-probe-boundary` before our own inspector DOM/style work, motion, viewport and input stress begins, so those stimuli do not pollute loading metrics. Short passive windows can remain explicitly unmeasured and can fail strict mode; use an appropriate controlled performance profile rather than interpreting missing data as zero.

Dynamic overlay evidence (`dynamic-accessibility.json`) includes forward/reverse focus, explicit menu arrow advance, native light-dismiss outside/drag boundaries when supported, and manual/closedby=none policy observations. No arbitrary explicit close action is clicked. Native support gaps, absent outside space and developer-controlled workflows remain visible instead of becoming false failures. System back gestures, custom fallback scripts, submenu/typeahead and destructive/dirty-form decisions still need feature-specific contracts.

Verification for this expansion: 55 Modern Web fixture cases passed across desktop/mobile Chromium, Firefox and desktop/mobile WebKit; 10 vitals cases passed, including historical visibility/fallback and observed bitmap LCP; five dynamic accessibility cases passed in Chromium; shared-page and reporting acceptance passed. The actual `43-modern-web.spec.ts` entry ran against six local Shopify and five local WooCommerce URLs, attached all three evidence families and sent no probe writes to the fixture server. `pnpm check` passed with 90 unit tests. Navigation-timing calibration uses a real loopback HTTP response because mocked fulfillment can omit requestStart. No live stores or full acceptance-suite run were used.

2. Search/retrieve current guidance for the area being changed. Compare it with this registry and the code. Upstream updates do **not** silently change store verdicts.
3. Update the shared implementation, the rule registry, the complete catalog mapping and their limits together. Recompute the guide-status summary when coverage changes. Preserve rule IDs unless their meaning changes. Bump the artifact schema version for incompatible structure changes.
4. Add local fixtures for both a real defect and a legitimate alternative. Keep heuristics advisory until a reliable behavioral assertion exists. Never validate a rule by submitting a real password/order or contacting a live store.
5. Run `pnpm test:modern-web:local`, `pnpm test:pages:local` and `pnpm check`. Modern Web fixtures run in `pnpm test:acceptance:local` in CI. Verify Shopify/WooCommerce and mobile spec discovery when adding/renaming suites.

## Suggested implementation order

1. **Remaining form workflows:** trusted OS IME behavior (`ime-safe-enter-submit`), sandbox password-manager/address autofill and full asynchronous validation/failed-submit focus. Initial/invalid/corrected native field/select evidence and semantic autofill hints already exist; extend those rather than duplicating them. Never attempt successful live submissions without a configured sandbox contract.
2. **Optional interaction contracts:** carousel autoplay/pause, localized controls and scroll-track behavior remain open after bounded next/previous samples. Expand existing Partial tab/menu/accordion/tooltip/modal samples for keyboard boundaries, root-focus tab operation, tooltip hoverability, safe dismissal restoration and touch only where the feature and expected outcome are explicitly identifiable.
3. **Loading and font resilience:** existing LCP attribution, media request observations, preload/script hints and long-frame diagnostics are Partial. Add controlled font delay/failure/swap, hidden-slide loading and stronger request-role/priority evidence; do not relabel heuristics as actual browser scheduling or field INP.
4. **Policy/privacy depth:** integrity/CORS/referrer and authored CSP/Trusted Types/Connection-Allowlist observations already exist. Actual enforcement, consent lifecycle/retention/deletion, worker/data-flow obligations and platform parity still need owned fixtures or explicit policy contracts. Watch for publication of the picomatch fix; TypeScript 7 remains blocked by parser compatibility.
5. **Device and component resilience:** real OS text scaling/keyboards, optional theme-toggle persistence, custom-component form reset/restore, closed-shadow limitations and configured SPA/scroll/gesture workflows remain open. Existing open-shadow names/references/disabled-participant samples, text stress, table/progress semantics and preference contrast samples are not complete certification.

These priorities reflect the November 18 handoff, not the original implementation plan. The matrix gives the exact Pending/Partial status and limitation for every guide. Feature absence is not a storefront defect, and required human/device/business contracts must remain explicit. Preserve the existing evidence schema and advisory-versus-blocking behavior while expanding coverage.
