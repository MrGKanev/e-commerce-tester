## What runs in the tester

The tester implements a reviewed subset of [GoogleChrome Modern Web Guidance](https://github.com/GoogleChrome/modern-web-guidance). The installed skill supplies development guidance; the executable checks below actually inspect stores.

Implemented on 2026-11-17, against upstream revision `64a6d708f5a43f2cd3fde5d4d7db3905ba1bdf65`. This records the review source, not an update pin. The rule registry and implementation live in [tests/modern-web.ts](../tests/modern-web.ts); local fixtures are in [checks/modern-web.spec.ts](../checks/modern-web.spec.ts).

The checks run in **Full** (`43-modern-web.spec.ts`) for every configured inventory URL, and in **Pages** on the document already visited by the shared-page audit, including discovered inventory pages. They support Shopify/WooCommerce and desktop/mobile projects. Full does not add discovered products to this suite; use Pages for those. Smoke remains unchanged. The control panel's existing Full and Pages selections include these checks.

```bash
# These commands visit the configured store.
pnpm test:modern-web --site=my-store
pnpm test:modern-web --site=my-store --project="Mobile Chrome"
pnpm test:pages --site=my-store

# Offline verification; no store requests.
pnpm build:css
pnpm test:modern-web:local
pnpm test:pages:local

# Additional engines, when installed locally (CI installs Chromium only).
pnpm test:modern-web:local --project=Firefox --project=WebKit --project="Mobile WebKit"
```

## Implemented rule registry

| Rule ID | Observation | Result | Source guide |
| --- | --- | --- | --- |
| `image-lazy-high` | A rendered image combines lazy loading and high fetch priority | Advisory: conflicting loading signals | `optimize-image-priority` |
| `image-viewport-lazy` | The largest rendered image intersecting the viewport is lazy-loaded | Advisory: verify this is the LCP image before changing it | `optimize-image-priority` |
| `image-high-overuse` | More than two document images request high priority, including hidden images | Advisory: review competing critical resources | `optimize-image-priority` |
| `form-description-reference` | An enabled, rendered control references a missing `aria-describedby` ID or a missing active `aria-errormessage` ID | Error: fails the scenario | `forms` |
| `form-invalid-feedback` | An explicitly invalid control has no referenced description/error text | Advisory: review useful error feedback | `forms` |
| `form-password-get` | A password field belongs to a form whose native method is GET | Advisory: JavaScript may intercept submission; this is not proof of a credential leak | `forms` |
| `form-password-autofill` | A password field lacks `current-password` or `new-password` autocomplete | Advisory: review password-manager support | `forms` |
| `video-captions` | A rendered video with a source has no caption/subtitle track; muted autoplay video without native controls is excluded as potentially decorative | Advisory: audio content, caption quality and external player controls need review | `accessibility` |
| `motion-reduced-unchanged` | A running infinite spatial animation in the viewport keeps identical keyframes without slowing down under reduced motion | Advisory: verify essential motion and pause controls | `motion` |

Zero observed elements means that category was absent from the inspected scope, not that its features comply. Unavailable animation inspection (unsupported API, hidden document or no animation frames within one second) records `motionSupported: false`. Missing modern APIs and equivalent custom components are not failures.

## Evidence and interpretation

Open the run's Playwright HTML report from **Reports**, expand a `modern web` or shared-page scenario, and open its attachments:

- `modern-web.txt`: findings with rule, severity, guide ID, element selector, observed facts and suggested fix.
- `modern-web.json`: schema version 1, URL, viewport, element counts, animation support/counts and structured findings.
- `modern-web-warning` annotations: recommendations are recorded even on passing scenarios.

Errors enter existing failed-scenario reporting/comparison. Recommendations do not reduce pass rate. Passing means the checks completed without a detected blocking error; review recommendations separately. There is no aggregate Modern Web score or automatic finding-resolution tracking yet.

The audit reads the current main document and compares no-preference/reduce motion after two animation frames. It restores the originally observed preference in `finally`. It does not fill fields, submit forms, click controls, scroll or navigate a second time. The site may fetch its normal resources in response to media changes. Full adds one visit per configured URL; Pages reuses its existing visit. Existing pacing, rate-limit handling and browser fixtures remain active. Input values and form action URLs are omitted from evidence; page URLs/selectors still need the usual care when sharing reports.

## Limits of this first implementation

- The largest viewport image is a heuristic, not measured LCP. No field INP is produced. Missing width/height attributes are not treated as layout defects: CSS or containers may reserve space correctly.
- Caption presence does not establish quality; absence may have an accessible external player or no meaningful audio. Decorative-video detection is heuristic.
- Motion covers currently running infinite spatial animations in the viewport. It excludes finite/interaction-triggered animations, canvas, animated images, flash limits and pause-button operation. Slower or changed-keyframe alternatives are accepted for review, not certified safe.
- Forms are not submitted, so actual validation flows and credential transport are not established. Error text may be generic. Missing references can be transient: confirm reproducibility before fixing the store.
- Hidden/disabled controls, shadow roots and iframes are outside the initial DOM scope. Empty/unsupported scope must not be read as comprehensive compliance.

## Maintenance process

1. `pnpm guidance:sync` refreshes the official skill/catalog at the start of relevant development tasks, as required by [AGENTS.md](../AGENTS.md). No maintained upstream-guide copy is committed. Store runs never download or execute the skill.
2. Search/retrieve current guidance for the area being changed. Compare it with this registry and the code. Upstream updates do **not** silently change store verdicts.
3. Update the shared implementation, the rule registry, the complete catalog mapping and their limits together. Recompute the guide-status summary when coverage changes. Preserve rule IDs unless their meaning changes. Bump the artifact schema version for incompatible structure changes.
4. Add local fixtures for both a real defect and a legitimate alternative. Keep heuristics advisory until a reliable behavioral assertion exists. Never validate a rule by submitting a real password/order or contacting a live store.
5. Run `pnpm test:modern-web:local`, `pnpm test:pages:local` and `pnpm check`. Modern Web fixtures run in `pnpm test:acceptance:local` in CI. Verify Shopify/WooCommerce and mobile spec discovery when adding/renaming suites.
6. Record the review date, upstream source revision and changed coverage here. Run metadata already records the tester's Git revision and working-tree state, tracing the executable expectations to our code.

The existing dialog/popover checks remain in `tests/a11y-dynamic.ts`, verified by `pnpm test:a11y:local`. Image load failures, axe, responsive overflow, Lighthouse and synthetic vitals retain their existing suites.

Verification recorded on 2026-11-17: all 20 local Modern Web fixture cases passed across desktop/mobile Chromium, Firefox and desktop/mobile WebKit. The shared-page integration passed with one document navigation and both evidence attachments. `pnpm check` passed, including 90 unit tests. Spec discovery was verified for Shopify and WooCommerce across all five production browser projects. No live store runs or full acceptance-suite run were performed for this implementation.

## Recorded next areas

These are gaps, not active checks: interaction-driven validation/error announcements; pause/stop controls for automatic motion; real LCP-image attribution/load-delay diagnostics; browser-specific progressive enhancement; and a dashboard summary separating recommendations from errors. Each needs deterministic good/bad local fixtures before becoming a store verdict.

## Suggested implementation order

1. **Form feedback and input safety:** accessible-error-announcement, required-field-feedback, validate-input-after-interaction, select-menu-interaction, ime-safe-enter-submit and autofill-address-form. Reuse existing newsletter/checkout helpers, but validate good/bad cases locally without successful submissions.
2. **Loading evidence and attribution:** finish optimize-image-priority using actual supported LCP attribution, then add media deferral, preload/script-priority observations and long-frame script attribution. Keep heuristics advisory and mark unavailable browser observations explicitly.
3. **Interactive accessibility:** modal scroll containment, carousel pause/navigation and tabs; then keyboard/edge positioning for custom controls and overlays. Feature absence is not a defect.
4. **Security/privacy depth:** resource integrity/referrer hints and configured policy/consent lifecycle checks, with explicit platform parity. Controlled fixtures and scope contracts come before any invasive live probing.
5. **Broader resilience:** fonts/text scaling, theme/forced-color checks, shadow component behavior and optional SPA/scroll/gesture workflows. P2/P3 work remains conditional, not an instruction to add features to stores.

These waves group guide topics, not promised test counts. P1 is a starting order, not a claim that every P1 check applies to every store. Keep the existing nine rules and their evidence contract stable while expanding coverage.
