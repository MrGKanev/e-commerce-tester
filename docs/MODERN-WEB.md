## Bounded table-span occupancy — 2026-11-20

The existing passive data-widget inspector now adds `spanOccupancy` per sampled table and advisory **`table-span-overlap`** (`responsive-table`, warning). It follows a bounded subset of the [HTML row-processing algorithm](https://html.spec.whatwg.org/multipage/tables.html#algorithm-for-processing-rows): skip occupied starting slots, normalize native `colSpan`/`rowSpan`, then inspect the full new cell rectangle. A spanning cell can start in a free slot and still overlap a previously covered slot. `rowspan="0"` is limited to the current declared row group; thead/tbody/tfoot groups and nested tables are isolated. This checks HTML structural occupancy, not overlap of rendered CSS rectangles.

Only standards-mode native rendered table/section/row/cell layouts with explicit native row groups are covered. CSS-stacked/hidden cells/rows/groups, ARIA grids, direct programmatic tr children, unsupported cell ownership or positive rowspans requiring implicit rows remain `unverified`. Limits are 20 existing sampled tables, 200 cells, 100 rows, 100 row groups, 128 processed cell columns and 4096 attempted slot assignments per table. The separate group limit also bounds tables with many empty groups. Every warning is buffered until the complete bounded model succeeds; a later exclusion discards that table's provisional span findings. Unknown counts are null, not zero.

Observed metadata includes `checkedRows`, `slotAssignments` and `overlapPlacements`; each new warning exposes structural selectors and numeric group/row/column/span/overlapping-slot counts, not cell text or IDs. `automaticHeaderAssociationsVerified`, `otherTableModelErrorsVerified` and `renderedOverlapVerified` stay false. Empty slots/anchor completeness, inferred scope/header association and full table conformance are not certified. An observed zero overlap count is only the stated subset result.

Sources/why/how: [responsive-table](https://github.com/GoogleChrome/modern-web-guidance/blob/main/skills/modern-web-guidance/guides/ui-atoms/responsive-table.md), [accessibility tables/testing](https://github.com/GoogleChrome/modern-web-guidance/blob/main/skills/modern-web-guidance/guides/accessibility/accessibility.md), HTML [row groups](https://html.spec.whatwg.org/multipage/tables.html#algorithm-for-processing-row-groups) and [native span reflection](https://html.spec.whatwg.org/multipage/tables.html#htmltablecellelement). Exact URLs and rationale are beside the [implementation](../tests/modern-web-data-widgets.ts), [span fixtures](../checks/modern-web-table-spans.spec.ts) and [group-limit fixture](../checks/modern-web-table-span-limits.spec.ts). Bounds/exclusions are repository observation policy, not HTML authoring requirements.

No store interaction, DOM modification or explicit resource fetch is introduced. Valid spanning tables are accepted without a sticky/container-query/API requirement. `responsive-table` remains Partial; totals stay **1 Covered / 62 Partial / 48 Pending / 98 Not applicable**. ## Checkbox ownership and conditional reversal — 2026-11-20

The first five candidates can include exclusions; absence of a finding never means all page controls were sampled.

Before every Space, the routine checks exact node/context, expected state and focus, then uses global keyboard input so authored focus theft is not undone by locator refocusing. At most two Space keys are sent. Each key has a bounded 200 ms ownership observation window; a later state/context change makes the sample `unverified` and preserves authored data. If the first key does not change the binary state, no inverse key is attempted. `interaction-checkbox-keyboard` remains an advisory warning for no toggle or failed reversal in this bounded sample; this local window is not field INP or a merchant performance requirement. Mixed-state cycles and delayed/business workflows need separate contracts.

`before`, `toggled` and `restored` retain the observed keyboard states. New `status`, `keysSent` and `restoration` distinguish an actual two-key reversal (`method: keyboard`) from conditional native DOM fallback (`method: native-property`), unchanged state, or unverified restoration. Native fallback performs a synchronous owner/state comparison before setting checked and emitting input; after an authored input-reset change it stops before change. It never restores into replaced/changed controls. Custom widgets receive no direct aria-checked rewrite: if keyboard reversal cannot safely complete, their current state is retained and cleanup is explicitly `not-restored`. No claim is made about app reset/dirty flags, general focus/scroll restoration or actual AT speech. Original checked=true and checked=false binary states are both sampled.

## Limits of this first implementation

- The largest viewport image remains a heuristic. Where available, the separate foreground LCP entry supplies observed image attribution and timing subparts; restricted timing is null. No field INP is produced. Missing width/height attributes are not treated as layout defects: CSS or containers may reserve space correctly.
- Caption presence does not establish quality; absence may have an accessible external player or no meaningful audio. Decorative-video detection is heuristic.
- Motion covers currently running persistent spatial animations in the viewport. It excludes short/interaction-triggered states not currently running, canvas, animated images, flash limits and pause-button operation. Slower or changed-keyframe alternatives are accepted for review, not certified safe.
- No successful form submission is attempted. Guarded Full probes exercise bounded invalid/correction states; complete async validation and actual credential transport are not established. Error text may be generic. Missing references can be transient: confirm reproducibility before fixing the store.
- Hidden/disabled controls and iframes are outside the base DOM scope. A separate bounded component inspector now samples open-shadow naming, ARIA references and observable disabled form participants; closed roots/private internals remain unverified. Empty/unsupported scope must not be read as comprehensive compliance.
