Smoke checks homepage/catalogue and actual product/variation addition; full/commerce add public pricing, JSON-LD, unavailable/backorder behavior and checkout readiness. Shared inventory content/visual/page/performance suites use configured Woo URLs. Shopify-specific suites are not selected for Woo and vice versa. See [WooCommerce](WOOCOMMERCE.md).

`35-seo-inventory.spec.ts` is shared by Shopify and WooCommerce: metadata, canonical, JSON-LD and comparisons between the configured and discovered pages. Tags `@full`, `@pages`, `@seo`; JSON evidence `seo-inventory.json`. Run with `pnpm test:seo --site=<slug>`; local checks: `pnpm test:seo:local`. See [SEO inventory](SEO.md).

`36-buyer-journey.spec.ts`: a shared UI buyer journey for Shopify and WooCommerce in a separate visitor session, tagged `@journey` and `@full`. Local positive/negative fixture checks: `pnpm test:journey:local`.

Checkout and empty-cart assertions: `pnpm test:claims:local` covers both platforms. `17-checkout` separates reaching checkout from the required contact/address fields; `05-cart` and the WooCommerce empty-cart scenario check both the UI and the public cart. Evidence attachments: `checkout-interface.json`, `empty-cart.json`. No personal data is filled in and no orders are submitted.

`39-a11y-extras.spec.ts` complements axe on every configured page (Shopify and WooCommerce): a single `main`, uniquely named `nav` landmarks, skip links with a real target, `lang` matching the page language, blocked zoom, positive `tabindex`, generic link text, accessible names that omit the visible label (2.5.3), keyboard traps, visible focus, focus landing on a hidden element, reflow at 320px, and serious axe best-practice/ARIA findings. Tags `@full`, `@a11y`; evidence `a11y-extras.json`. Run with `pnpm test:a11y --site=<slug>`; locally: `pnpm test:a11y:local`. These are heuristics over the first 20 Tab stops, not a complete accessibility audit.

`40-a11y-dynamic.spec.ts` checks states that static axe cannot see: the menu, search and cart drawer open with Enter, an explicit `aria-expanded` reflects the open state, the dialog has a name, a modal dialog receives and holds focus (Tab/Shift+Tab), and dismissal follows its declared policy with focus return when closed. Explicit menu arrow advance and supported native light-dismiss/drag boundaries are also observed. Native dialogs and open popovers are supported without requiring redundant ARIA or custom focus traps; native modal focus may reach browser chrome. Variant options are named, grouped and changeable with arrow keys, and axe reports no blockers after a selection. The same file audits pages outside the configured inventory: the 404 page, policy/contact pages (Shopify), `/my-account/` (Woo) and discovered products, using axe and the checks from `39`. Controls and pages that a store lacks are marked `not-applicable`. Tags `@full`, `@a11y`; locally: `pnpm test:a11y:local`. No forms are submitted and the cart is not changed.

## Claims fixture port isolation — 2026-11-18

GitHub CI exposed a collision on legacy fixed port 45994. The parent claims acceptance runner now binds an OS-assigned loopback port before spawning Playwright and supplies its URL through STORE_URL. Workers no longer own a fixed-port server. Fixture-only mode/state endpoints preserve the existing assertions and counters; both platform servers close in finally. A Node regression occupies the old port (or accepts that it is already occupied), starts two independent dynamic-port fixtures and verifies no request reaches the unrelated listener. All 40 browser claims cases and the complete check (99 unit tests) pass locally after this change.
